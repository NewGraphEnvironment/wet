## Mechanism

One fact is put into two grammars, and the check holds only where they agree. Each half of the script turns one kind of fact into a pattern written for that half alone: a number with a unit (`unit_rx`), a listed figure (`whole_rx`), a figure's place in its source (`literal`, matched as a substring), a choice's place in the code (`anchor`, matched as a substring of any line, comment or code), a constant (`is_const`/`is_assign` over top-level expressions), a quotation (the strict `rx`, `mark_rx`, `pg`), and code (`` `[^`]*` `` over the whole file joined into one line). The thing it guards, prose as a reader sees it and code as R runs it, has a larger grammar than any of these. So whatever one grammar does not produce is never compared, and it reads as "nothing found", that is, as a pass. Rounds 1 and 2 were this: a substring matcher against a token-boundary extractor, then the sign class in one of the two and not the other. The round-2 fix made `unit_rx` and `whole_rx` agree with each other on `−` and `-`. They still both differ from the text: en dashes, other unit spellings, bold, other spaces. And the substring rule round 1 removed from the prose side is still used on the source side (`literal`, `anchor`). The script's own `clean()` already knows a wider dash set (U+2010 to U+2015, U+2212) and a wider quote set (U+201A, U+201E) than the figure half and `mark_rx` use. That is the same fact written three ways in one file.
