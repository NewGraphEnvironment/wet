## Findings

- **[severity: fragile]** scripts/scenario_basis.R:301-311 (with R/wet_pcic_fetch.R:36-47) — the gridded path logs a request only after `wet_pcic_fetch()` returns a new file, and logs it as one request with code 200. Every other request it makes is never written to `<data root>/logs/169/scenario_basis_fetch.tsv`: each 429/503 retry inside `wet_pcic_fetch()` (up to four extra requests per file), and any attempt that stops (another status, a non-NetCDF 200, a download with other days, a curl timeout). The header says "Every request made is logged to ... which the report reads", and the report's `requests logged:` line and `fetch_guard()` read only that log, so under `WET_SCENARIO_FETCH=1` the record of requests to a host whose robots.txt disallows the path undercounts, in exactly the runs that met refusals. The sibling caller `listing()` (scripts/scenario_basis_lib.R:87-93) logs every try with its real code, so the two request paths in one script keep different records. Fix shape: let the logging see each try (for example a logging hook or return value from the fetch loop, or log a failed attempt in a `tryCatch` around `wet_pcic_fetch()` with the status it stopped on), before any real run, since a rerun after the fact cannot recover the missing rows.
  - **Rule:** code-check.md "A fix lands in one of two callers that share a harness"
