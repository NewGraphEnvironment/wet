# Review round 3: #28 data-raw scripts (provenance mechanism)

Reviewer: code-check round 3, 2026-10-02. Probes run in the scratchpad, not in the repo.

## The mechanism

Both earlier defects come from one assumption: **the producer treated its own
session's context as the context the artifact is read in.**

- integer64: the writing session had bit64 loaded, so the saved ids "looked
  like" integers. A fresh session reading the rds has a different context, and
  the same bytes mean something else.
- commit: the writing session read its code from the working tree, and the
  provenance described a different object (HEAD). The claim "built at commit X"
  was derived from one source and the values from another.

The general form: every value written into `segment_values.rds`, and every
claim about where it came from, must be derivable from something the reader of
the rds can reach (base R types; a commit; a keyed input). Any input whose
state lives only on the producer's machine and is not keyed breaks the
"commit X can rebuild this" claim the dirty-tree guard was added to make true.

## Findings

- **[severity: bug]** data-raw/segment_vignette_data.R:141-156, 170 — the PCIC
  numbers (`parity`, `sampling`, `segments$mad_pcic_m3s`) come from the
  gitignored `data/parity/SALR_*.csv`, written by `scripts/mad_parity.R` through
  `wet_ws_sample()`, `wet_upstream_mean()`, `wet_pcic_*()` at whatever tree it last
  ran on. Nothing keys them: mad_parity.R writes no stamp (data/parity holds only
  the four CSVs), and the data script only checks existence and row count. The
  dirty-tree guard then records HEAD as the commit that "can rebuild the data",
  which is exactly the round-1 defect one hop upstream: a clean tree at HEAD
  says nothing about the code that produced these values. (Here all
  data/parity and data/wb files share an mtime to the second, 07:51-07:54 today,
  consistent with a copy from another run, so mtimes cannot answer it either.)
  Remedy shape: have mad_parity.R write a stamp beside its CSVs (md5 of the R/
  and script files it depends on, the way `wb_score_md5.R` does) and have this
  script refuse a mismatch; or at minimum record the CSVs' md5 in provenance so
  the claim is about the inputs actually used.

- **[severity: fragile]** data-raw/segment_vignette_data.R:34 — the guard's
  pathspec is `R scripts data-raw`, but the script parses three tracked reports
  outside it (`data/checks/wb_validation.txt` line 62, `upstream_area_100_full.txt`
  line 183, `stations_wb.txt` line 188) and writes values from two of them into
  provenance, which the vignette quotes (`hydat_release`, `upstream_area_100`).
  These are regenerated by scripts (`wb_validate.R <winner>` copies over
  wb_validation.txt, `wb_stations.R`, `upstream_area_check.R`), so a re-run leaves
  them modified, the guard passes, and the recorded commit carries different
  report text than the values were read from. Adding `data/checks` to the
  pathspec closes it.

- **[severity: fragile]** data-raw/segment_vignette_data.R:34-37 — the guard
  fails toward pass when git errors. `system2(stdout = TRUE)` on a non-zero exit
  warns and returns `character(0)` with a `status` attribute (measured: run
  outside a git repository, `git status` exits 128, `dirty` has length 0, guard
  passes; `rev-parse` likewise returns `character(0)`). So in a copy of the tree
  without `.git` the run proceeds and saves `wet_commit = character(0)`, which
  the vignette's inline `` `r prov$wet_commit` `` (Rmd line 405) renders as an
  empty code span, silently. Git missing from PATH, by contrast, errors (fails
  toward abort, fine). Run from a subdirectory, the relative pathspecs match
  nothing and the guard passes vacuously, but `source("scripts/wb_cv_lib.R")`
  aborts on the next line, so that path is caught by accident. Remedy: check
  `attr(x, "status")` on both calls and `stopifnot(length(wet_commit) == 1)`.

Not findings (checked): untracked files in the guarded dirs are listed by
`--porcelain` (no `status.showUntrackedFiles` set); no ignored files exist under
R/, scripts/, data-raw/; no skip-worktree/assume-unchanged index flags; the map
script records no commit, as accepted.
