## Findings

- **[severity: fragile]** data-raw/segment_vignette_map.R:76-79 and :164 — `n_cls` comes from `SELECT coalesce(p.source, 'none') AS class, count(*) ... GROUP BY 1` with no `ORDER BY`, and the provenance stores it as the named vector `drawn = stats::setNames(n_cls$n, n_cls$class)`. Its element order is whatever order the aggregate emits. `vm_write()` keeps the committed file only when `identical(vm_provenance(layers), vm_provenance(old))`, so a rerun on the same day, at the same commit, against the same FWA, whose plan emits the three groups in another order (a parallel plan's finalize, or a sort-based plan instead of a hash plan) rewrites `segment_map.rds` even though nothing changed. That is exactly the "rerun leaves the file as it is" property the branch claims for this script (header lines 26-28) and that CLAUDE.md states ("every query and aggregate ordered on a unique key"). The line is older than the branch, but the branch is what makes the provenance's order count. Fix: `GROUP BY 1 ORDER BY 1`, or sort `drawn` by name before storing it.
