## Mechanism

Two definitions of "what one group's rows need" coincide on the cases measured and are used interchangeably everywhere else. The code builds the *closure*: every polygon under the group's roots, a sufficient, upstream-closed superset. What a group's rows *need* is the FWA_Upstream set of its own polygons, and the two are equal only when the group holds the mouth (lowest localcode) of each root's stream. BULK does (it holds `400.431358` at localcode `400.431358`), so on the case the prose was first written from they agree. Off that case they part company: SALR does not hold the Salmon's mouth (LSAL does), and the Fraser-main-stem groups above LFRA/FRCN hold no polygon with localcode = wscode. Earlier rounds' findings 3-5 are the same shape: a sentence states a set or a capability by a nearby notion verified on the cases at hand (BULK and SALR, the plain run, the dev machine) rather than by what the code computes over the whole population. Findings 1-2 are its code form: an assumption true of the default run or the dev machine (one output per group; httpfs already installed).

Measured in fwapg (read-only), for the cases the prose names:

- SALR: FWA_Upstream from SALR's 4,587 polygons reaches 4,589 polygons (SALR's own plus 2 of LSAL's), against a closure of 12,481 in LSAL, MUSK and SALR. SALR's lowest Salmon main-stem polygon is at localcode `100.591289.413213`; LSAL holds the mouth (`100.591289`).

KUMR's `910` polygons have localcodes 910.707297-910.774898, none equal to `910`, and its closure is all 243,507 polygons under 910/915.

## Findings

- **[severity: bug]** research/segment_group.md:9-11 and :28; R/wet_ws_closure.R:31,33; scripts/segment_group_closure.R:1,5,83,86 (and the generated data/checks/segment_group_closure.txt); CLAUDE.md:23; research/README.md:15; issue #157 body ("What a group needs", candidate step 2) - the closure is a sufficient set, but every one of these says it is what the group needs. fwapg contradicts the named cases. SALR's rows need 4,589 polygons (SALR plus 2 of LSAL's), not "LSAL and MUSK (12,481)": LSAL holds the Salmon's mouth and is downstream of SALR. LNRS's rows need about 34,000 polygons in 6 groups, not "18 others (116,474)": LCHL and CHES lie below it on the Nechako. UFRA's rows need about 23,300 polygons in 2 groups, not "all of" the Fraser's 644,770 in 82. "These groups need all of that river or drainage" is false for every one of the 48 that does not hold its root stream's mouth (on the Fraser only LFRA and FRCN do). #157's step 2, "resolve the groups upstream of it ... (Done)", describes something the code does not do: it resolves every group under the group's roots, downstream and sideways ones included. The sums are still correct, because a superset that is closed upstream is enough. The defect is in the claims and in the cost they imply (the bins and the 48 count measure closure size, not need). Wording that is true: "the polygons under its roots, a set closed upstream that contains everything its rows need". The named examples need correcting, or need restating as closure sizes.

- **[severity: bug]** R/wet_ws_closure.R:42-44 - the roxygen says a group needs its whole basin when it holds a polygon with `localcode == wscode` at a basin root. The code (`wet_ws_roots()`) takes the whole basin whenever any of the group's polygons has a basin-root wscode, whatever its localcode. UFRA, COTR, MORK and TABR (Fraser main stem, lowest localcodes 100.843983, 100.458476, 100.632108, 100.531379) and KUMR (`910`, localcodes 910.707297-910.774898) hold no `localcode == wscode` polygon, yet each gets its whole basin. The doc's condition is not the one the code applies, so a reader predicts small closures for these groups that the function does not return. The closure script header (line 5, "a group holding a mainstem polygon needs its whole basin") states the code's condition but with "needs", which is false (first finding).
