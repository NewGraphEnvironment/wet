## Findings

- **[severity: fragile]** scripts/wb_small_basin.R:255-257 — check C reads data/wb_term/diagnose_<release>.rds and checks only `tm$release`. That rds carries no province-run key or scoring md5, and its `basins` hold the `cv_ann`, `p_yr`, `aet_cfu` of whatever fit existed when scripts/wb_term_diagnose.R last ran. The script refuses a fit whose md5 it does not reproduce for `cv`, but C's population and its printed "median error there: raw ..., adjusted ..." would silently come from an older fit after a refit within the same release (as at #76 and #163, both on 20260717). The copied-verdict check does not catch it: it recomputes from the same cache it reads, so it agrees by construction. Today the cache matches (probe above), so the report's numbers are right. A guard would be to hold the cache's single-gauge `cv_ann` to `cv$cv_ann` by station before C runs.
  - **Rule:** code-check.md "A proxy is not the property" ; code-check.md "Verification that reads its own output"

- **[severity: fragile]** scripts/wb_small_basin_rule.R:37-38 and :85 (registered at 9f5a0da alongside the header) — two outcomes the functions can return are not in the header's registered text. The header (lines 37-39) says A's reading is "general" or "concentrated". sb_reading_contrast() also returns "unreadable" when a split has no readable class, and under the header's wording that case would read "concentrated". The header (lines 90-92) says the attribution is "ours, P" or "ours, AET", "otherwise unresolved". sb_attribution() maps C's "P side, shared (ours and theirs)" to "ours and theirs, P", where the header's wording gives "unresolved". Neither branch is reached in this run (A reads "concentrated" with 3 readable classes in each split; C reads "compensating"), so no published number or verdict moves. The header and the functions were registered in one commit, so they disagree on these two cases.
  - **Rule:** code-check.md "A guard's scope, escape hatches, and remedies"
