# Task: Backlog move 17: Provincial station records, current copy and Hakai's early years (#210)

**If we do it:** we know which copy of the province's 2021–2026 non-integrated discharge is current, and the three Hakai stations on Calvert and Hecate islands gain their 2013–2020 record, enough years to serve as donors and test sites on the central coast. **If we never do:** those provincial years stay of unknown standing, and wet reads the Hakai stations from 2021 only.

Batch 19 (one phase per member, one PR): #190 (which copy of the province's 2021–2026 discharge is current, from its Aquarius portal), #192 (Hakai's 2013–2020 discharge at its three Calvert and Hecate stations), #207 (consolidate `research/station_sources.md` around the current state).

- **Phase order: #190, then #192, then #207 last.** `research_check.sh` flags `research/station_sources.md` for words only (`words=5004`, over its 3,000; `sections=0` counts issue-headed headings, and the file has 13 plain `##` sections). #190 and #192 each add findings to that file, so consolidating last lets the check pass on the file as it ships.
- **Hakai gets a registry of its own,** `inst/extdata/station_sources/hakai_<version>_hydat.csv`, not rows in the Water Tool's registry. `wet_station_regulation()` (`R/wet_station_list.R:125-135`) and `scripts/station_regulation.R:58-61` hash only the bcenv and Tool registries, and every Hakai row continues a provincial station, so `wet_regulation_of()` never asks the status file for a Hakai number: the regulation file stays valid and #196's run is not repeated. The registry's columns: Hakai's id, watershed, name, coordinates, `continues`, `continues_before`, `first`, `last`, `licence`, `credit`, `bcenv_snapshot`, `bcenv_days` (the last two as the Tool registry's, since `continues_before` is measured on one provincial snapshot and reader version), with a check like `wet_bcwatertool_against()` (`R/wet_bcwatertool.R:235-249`) refusing a registry built on other provincial days. A row with no `continues` is refused at the pin and on read: it would be a station with no regulation row.
- **The continuation is the Tool's rule, shared, not copied, and landed first as a pure refactor.** The cut-and-rename in `wet_bcwatertool_station_days()` (`R/wet_station_daily.R:187-191`) and `wet_station_list()`'s splice of a continued station's `first`, `last`, `licence` and `credit` (`R/wet_station_list.R:79-95`) move into internal helpers taking any continuation registry, with the licence text from the registry's own `licence` column (the Tool's rows keep "none stated"). That commit changes no output: the existing Tool tests pass unchanged before any Hakai code exists.
- **One registry check over the registries a call opens.** `wet_registry_check()` refuses a number held by two registries and a provincial station continued by two publishers, raising class `wet_registry_conflict` so `wet_daily_try()` (`R/wet_station_daily.R:222-232`) re-raises it rather than skipping the source. *Corrected at the build:* reading every registry whichever `sources` are asked would break the shipped test that a call without `"bcwatertool"` never opens the Tool registry (`test-wet_station_daily.R:447`), and a call that leaves a source out cannot count a day twice; so the check covers every registry the call opens, a test holds the three shipped registries free of conflict, and the Hakai pin refuses a station the Tool already continues.
- **`sources = "hakai"` switches on the continuation only.** Hakai has no station of its own here, so `wet_station_list(sources = "hakai")` alone returns a typed zero-row frame (not `NULL`, which `do.call(rbind, list())` gives). `"hakai"` joins the default `sources` of both functions, as `"bcwatertool"` did; `tests/testthat/test-wet_station_list.R:47-51`'s set of moved provincial rows then gains H08KC0626, H08KC0703 and H08KC0844.
- **A Hakai day is read as a provincial day is:** a local-standard-time day (UTC−8) with at least 20 hours, from the package's hourly series; the bound is `wet_bcenv_bound` with `sub = "08K"` passed explicitly to `wet_bcenv_ratio()` (`R/wet_bcenv_daily.R:84-91`; Hakai's own ids carry no sub-drainage and would fall to `.default`), times the median of Hakai's own positive complete-day flows. The day rule, bound and flag-to-status mapping are registered in `research/station_sources.md` before any day is counted, as #179 and #195 registered theirs; an unlisted flag is refused, as the provincial grades are. What `status` a Hakai day takes is decision 5.
- **Identity by watershed number and coordinates, since the records do not overlap.** The package ends 2019-09-30 and the provincial records begin 2021-10-01, so no common day can be compared. The pin holds each package station to its provincial row by watershed number in the name (626, 703, 844) and by distance within the survey's same-site 0.5 km (`research/station_sources.md`, "A provincial record continued"), refusing past it.
- **The 2019-10-01 to 2021-09-30 gap is expected.** `wet_station_daily()` warns on a gap between sources (`R/wet_station_daily.R:238`); a test asserts that warning for these years, so it is documented behaviour, not a surprise.
- **Pin scripts keep their helpers out of `scripts/station_sources_lib.R`.** `scripts/station_regulation.R:31-41` refuses to run once that file differs from commit 6c9cb1e5; Phase 1 and 2 helpers go in their own scripts or in `R/`.
- **Donors are not delivered by this move.** The three H08KC stations are `unknown` ("no accepted snap", `regulation_20261028.csv:210-212`), so a natural-donor pool (#202) leaves them out until they are placed on the stream network. The PR and #192's body say so; placing them is not in this move.
- **A new provincial pin is out of scope.** If #190 finds the pinned files are the stale copy, a newer snapshot rebuilds all three registries (provincial, Tool, Hakai), the regulation status file and the harvest report: it is filed as its own issue naming move 17, left out of `planning/backlog.md`, per the backlog's split rule.
